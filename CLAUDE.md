# Jot: agent rules

Local-first notes PWA. React + TipTap + Yjs, synced via Cloudflare Durable Objects. Free plan only.

**Read `docs/project-context.md` first.** It is the source of truth for architecture, decisions and traps. If a change contradicts it, raise that instead of silently diverging.

## Workflow

1. Check `docs/plans/` before starting a feature or fix. Create a plan there if none exists.
2. Local-first always: the UI reads and writes the local Y.Doc, never a server API, for note data.
3. All sync-provider code goes through `src/sync/provider.ts`.
4. After any sync, storage or editor change, test with two tabs (one offline).
5. Update the §10 checkboxes and §12 decisions in `docs/project-context.md` when something is done or decided.

## Commands (pnpm only)

- `pnpm dev`: app + Worker locally
- `pnpm preview:worker`: build + `wrangler dev` on `http://localhost:8787` (real Worker-first routing)
- `pnpm check`: lint + format check + typecheck. Run before saying work is done.
- `pnpm lint:fix` / `pnpm format:fix`: apply fixes
- `pnpm run deploy`: build + deploy (never `pnpm deploy`, a different built-in command)
- `pnpm db:migrate` / `pnpm db:migrate:remote`: apply `migrations/` to local / real D1
- `pnpm dlx shadcn@latest add <name>`: add a shadcn component, only when a feature needs it

A pre-commit hook lints and formats staged files. Never bypass it with `--no-verify`.

## Conventions

- File names are kebab-case (`account-footer.tsx`, `local-data.ts`, `use-auth-user.ts`). React hooks get their own file in `src/hooks/`, except sync hooks, which stay in `src/sync/provider.ts` (rule 3).
- Imports in `src/` use the `@/` alias, never `../` (lint error).
- Import React as a namespace: `import * as React from "react"`, then `React.useState`, never `import { useState } from "react"`.
- No `fetch` in `src/editor/` or `src/features/notes/` (lint error).
- Do not hand-format or lint `src/components/ui/` (generated by shadcn).
- After editing `wrangler.jsonc`, run `pnpm cf-typegen`.
- Keep it small. Add packages only when their phase starts (context §6). Flag any paid service or package.

## Never

- Install `@tiptap-pro/*`, use Tiptap Cloud, or Hocuspocus.
- Hard-delete notes (use `deleted: true`).
- Store note content outside Yjs, or put all notes in one Y.Doc.
- Trust the client for permissions or roles. The Worker checks every connection and overwrites `x-jot-role` / `x-jot-user` itself; after changing someone's role, close their connections (code 4401) so they reconnect with it.
- Enable TipTap's own undo/redo alongside Collaboration.
- Edit an existing Durable Object migration or an applied D1 file in `migrations/`. Add a new tag / file.
- Put secrets in `wrangler.jsonc` or git. Local: `.dev.vars`; production: `wrangler secret put`.
- Cache `/api/*` or `/parties/*` in the service worker, or drop them from `navigateFallbackDenylist` (the Google callback and sockets must reach the Worker). `/privacy` and `/terms` (static pages in `public/`) are in it too; never add `/join/` or `/share/`, which are app routes.
- Let a precached file pass 2 MiB (Workbox skips it silently and offline start breaks). Test the service worker with `pnpm build && pnpm preview`, never `pnpm dev`.
- Test the permission guard only with `pnpm dev`: also check it against `pnpm preview:worker` (build + `wrangler dev` on `http://localhost:8787`), where the Worker-first routing is real. Plain `wrangler dev` breaks Google login (context §11).
